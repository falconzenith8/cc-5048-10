# 实景虚拟展品合成器（实景遮挡内核）

接收带相机标定的**颜色帧 + 深度帧**，把三维虚拟展品放入与实景相同的
世界坐标系，逐像素比较「虚拟投影深度」与「实景深度」，决定虚拟物应被
现实前景遮住，还是显示在现实前方。遮挡判定由真实深度驱动，**不使用
手绘前景轮廓遮罩**；没有硬件时使用带真值的模拟录制，并提供逐像素真值
核对。

## 1. 怎样启动界面

依赖：Python 3.10+、numpy、pillow（Web 服务只用标准库，无框架依赖）。

```bash
# 安装依赖（无 root 时加 --user --break-system-packages）
python3 -m pip install numpy pillow

# 一条命令：先跑 16 项内核自检，再启动界面
./run.sh
# 或手动启动
python3 tools/generate_data.py --frames 12 --out data/demo   # 生成带真值录制
python3 -m occlude.server --port 8000 --data data/demo
```

浏览器打开 <http://127.0.0.1:8000/> 即进入**空间音画视窗**：

- 左侧视窗可切换：最终合成 / 配准深度 / 有效掩码 / 边缘诊断 / 参考真值 / 纯实景；
- 右侧控件移动虚拟展品（X/Y/Z 毫米）、调深度容差、开关缺测高亮；
- 底部滑块沿移动相机轨迹选帧，可播放；
- 「开启空间音频」后声源跟随展品屏幕位置，被现实遮挡时自动低通+衰减；
- 「核对参考位姿真值合成」逐像素比较当前内核输出与录制真值。

仅运行脚本不算完成：界面是真实可用的 HTTP + 浏览器应用，内核自检
（`python3 tools/selftest.py`，16/16）覆盖外参、配准、遮挡方向、缺测、
边缘诊断、越界拒绝与整条相机轨迹。

## 2. 深度定义与相容口径

- 相机坐标系：OpenCV 约定（X 右、Y 下、Z 朝前）。
- **深度 = 沿光轴的 Z 距离，单位毫米**。虚拟渲染深度（`rasterize.py` 的
  z-buffer）与配准后的实景深度都在**颜色相机坐标系**下，因此可直接逐像素
  比较，无需单位换算或视角转换。
- 原始深度单位与无效值不写死：`DepthCamera.depth_scale`（原始单位→毫米）
  与 `invalid_value` 在 `decode_depth` 中单独处理；模拟录制为
  uint16、1 单位=1 毫米、0 为无效值。
- 深度相机与颜色相机是**两台独立相机**，各自有内参；深度→颜色必须经过
  完整三维链路：
  `深度像素 → 深度相机系点云 →（外参 R_cd, t_cd）→ 颜色相机系 → 颜色像素`
  （`calibration.register_depth_to_color`）。**不能把深度像素坐标直接当成
  颜色图坐标**——两者内参不同且存在 30/15/40 mm 的基线偏移。
- 同色像素多点命中取最近（z-buffer），落在画面外的点丢弃，**不做插值或
  孔洞填充**。

## 3. 遮挡判定规则

对每个被虚拟物覆盖的颜色像素，令 `Δz = z_real − z_virtual`，容差 `bias`
（默认 10 mm，界面可调）：

| 条件 | 关系标签 | 合成动作 |
|---|---|---|
| `Δz > bias`（虚拟更近） | `virtual_front` | 用虚拟颜色覆盖实景 |
| `Δz < −bias`（实景更近） | `real_front` | 保留实景，虚拟物被前景遮住 |
| `|Δz| ≤ bias` | `near_planar` | 50/50 混合，避免 z-fighting |
| 实景深度无效 | `real_missing` | 绘制虚拟但橙色斜纹高亮并计数告警 |

### 近裁剪、远处缺测、透明物体的支持范围

- **近裁剪**：`near=150 mm`。三角面任一顶点在近面内则整面剔除，命中像素
  计入 `near_clipped_px`，界面统计中可见，不静默丢弃。
- **远裁剪**：`far=6000 mm`，超出计 `far_virtual_px`。
- **远处缺测**：深度无回波 ≠ 无限远。缺测像素上的虚拟内容仍绘制，但
  ① 单独计数 `missing_px`；② 橙色斜纹高亮（可关高亮但统计不消失）；
  ③ 内核消息区给出中文告警。模拟录制在桌面区域挖了一块矩形缺测，专门
  验证这条路径。
- **透明现实物体（玻璃等）**：主动深度传感器对透明表面通常无回波，本
  实现将其归入「缺测」而非错误地当作可穿透的无限远。这意味着透明板后的
  虚拟物会被画出并标记为低可信，**不声称已正确处理玻璃折射/透射**。

## 4. 边缘配准诊断（偏差可见）

`edge.py` 分别提取颜色边缘（Sobel + 平滑 + 多数滤波去噪）和深度边缘
（有效像素间的深度跳变，排除缺测边界），以深度边缘为基准计算到最近
颜色边缘的倒角距离：平均/95 分位/最大距离与匹配率。叠加图中绿色=两侧
边缘重合、黄色=仅颜色边缘、青色=仅深度边缘。自检会人为把深度光心横向
扰动 60 mm，证明该诊断能捕获标定错误（匹配率 100%→约 45%，平均距离
0.01→5 px）。

## 5. 录制格式（无硬件时的带真值数据）

`data/demo/`（由 `tools/generate_data.py` 生成）：

```
meta.json     双相机内参、深度→颜色外参 R_cd/t_cd、深度单位/无效值、
              近远裁剪面、每帧颜色/深度外参（移动轨迹）、参考展品位姿
color_XXXX.png   颜色帧（RGB）
depth_XXXX.png   深度帧（uint16，毫米，0=无效，含模拟缺测矩形）
gt_XXXX.png      真值合成：真实场景+参考位姿展品单次 z-buffer 渲染
```

场景包含：合成桌面、红色前景遮挡板（在展品与相机之间，只遮挡展品上半
部分）、带色块纹理的后墙、三层塔状虚拟展品。颜色相机沿 12 帧圆弧轨迹
移动，深度相机相对颜色相机固定偏移。`occlude.dataset.load_recording`
可直接读取同格式的真实录制——接入真实硬件时只需把数据写成该格式。

## 6. 真值核对

- 离线：`tools/selftest.py` 在参考位姿比较内核合成与 `gt_*.png`，要求
  平均色差 < 25、严重不一致像素 < 5%（当前实测 MAE≈0.03、不一致≈0.02%）。
- 在线：界面「核对参考位姿真值合成」按钮调用 `/api/gt_check`，自动排除
  缺测斜纹区后报告 MAE 与不一致占比。

## 7. 内核如何驱动控件、失败如何反馈

- 允许移动范围定义在内核 `pipeline.MOVE_LIMITS`，由 `/api/info` 下发给
  前端设置滑块边界，前端不写死。
- 越界位姿、非法帧号、未知视图由内核抛 `PipelineError`，服务返回
  HTTP 400 + 中文错误，前端在视窗顶部红色横幅回显（例如
  `虚拟物 x 轴偏移 9999mm 超出内核允许范围 [-700, 700]mm`），不吞错误。

## 9. 深度测试相机（可控薄板扫动回归装置，纯标准库）

为合成器建立的一台**可控深度测试相机**位于 `occlude/depth_rig/`，零第三方
依赖（不 import numpy，因此在未安装 numpy 的环境也能运行）。它用一台沿 +Z
观察的**正交相机**（毫米、OpenCV 约定）让一块带孔薄板横向扫过虚拟展品。

```bash
python3 tools/depth_rig_regression.py     # 23 项回归断言，退出码 0=全通过
python3 tools/depth_rig_http_test.py      # 18 项 HTTP 集成断言（真实起服务）
python3 tools/depth_rig_server.py --port 8100   # 回放界面，浏览器打开该地址
# 装有 pytest 时亦可：pytest tools/test_depth_rig.py
```

### 9.1 观测三件套与独立射线区域

每个像素是一条平行于 Z 轴的独立射线，与薄板在 `z=z_plate` 处求交，逐射线
给出互斥的区域真值（`geometry.py`，不读取传感器输出）：

| 区域 | 含义 |
|---|---|
| `occluded` | 落点在板实体，射线被薄板挡住 |
| `hole_visible` | 落点在某孔内缩区域，穿过孔直达后方展品 |
| `edge_uncertain` | 距板外轮廓/孔轮廓 ≤ 边缘带半宽，单独标为不确定带 |
| `free` | 板外自由射线 |

传感器（`sensor.py`）逐帧产出：当前帧**真实颜色**、固定**延后一帧**的深度
（第 t 帧深度来自 t-1 几何）、以及**有效位标志**。被声明无效的区域
`valid=False` 且 `depth=0`；数值 0 本身无语义，一切以有效位为准。

### 9.2 四种故障与其互不重叠的失败区域

回归在测试帧上断言每个故障的失败像素非空、被限制在声明区域内，且四种失败
区**两两互斥**（`regression.py`）：

| 预设 | 故障 | 失败区域（独立射线几何推导） |
|---|---|---|
| `unit_error` | 远表面深度按 1.08 放大（单位换算 bug） | 仅板外、来源帧前后标签稳定的远自由射线（深 ≥1200mm） |
| `temporal_mismatch` | 忽略一帧时延，用当前几何深度 | 仅相邻帧区域标签变化的边缘扫动条带，静止薄板时为 0 |
| `hole_fill` | 孔内用板深度回填 | 仅 `hole_visible` 像素 |
| `missing_as_occluder` | 缺测一律当最近遮挡物 | 仅 `valid=False` 的缺测像素 |

速度/距离对照由 `ReplayInterface` 提供：拖慢薄板（18→3.75 mm/帧）后时间
错配失败像素由 553 降到 48、静止时归零，而把板平面平移 150mm 其规模不变，
证明时间错配**随速度而非距离**变化；单位错误则与速度无关、只由射线深度
决定。

### 9.3 零深度无效区与邻近近表面

想定在右下方布置一块 `valid=False, depth=0` 的无效矩形，与一片真实位于近处
（z=520mm）的表面只隔 2mm 间隙，另有一枚孤立无效像素。正确合成器把这类
像素判为 `missing_invalid`（保留颜色、深度 0、显式标记）；回归能检出
`missing_as_occluder` 把它们改成板色/板深度的错误，并断言其失败区与时间
错配扫动条带互斥，**不与帧延迟失败混为一谈**。边缘不确定带优先级高于缺测。

### 9.4 断言直接读取最终显示缓冲

合成器输出 `DisplayBuffer`（颜色/深度/状态/统计），这就是最终显示缓冲。
回归与界面读取同一份数据：HTTP 层测试逐像素断言 `/api/frame` 返回的缓冲
等于内核 `DisplayBuffer`，前端 `depth_rig_web/app.js` 也只绘制该缓冲，
不自行重算遮挡。回放接口可回传单个失败帧及前序时间戳（`history` 参数）。

## 10. 已知限制

1. 配准为整数像素最近邻，深度视图有量化条带；未做亚像素插值（有意保留
   缺测，不以插值掩盖无数据区）。
2. CPU 光栅化按三角面循环，面向小网格演示场景，非实时大模型渲染器。
3. 透明/镜面现实物体按缺测处理，不模拟折射反射。
4. 模拟深度为理想几何深度加缺测，未模拟真实传感器的飞点/多径噪声。
